Reviewed `master` at `929b1f6db4a4ce76ce49142dfd92c9847f94fff4`, firmware v2.0.9, from https://github.com/catorendal-a11y/DIY-Welding-Positioner-ESP32-P4.

## Scope and assessment

Reviewed startup, safety, command dispatch, motor control, pedal/ADC input, program execution, parts of storage/UI, tests and hardware documentation. Physical wiring and motor response were not measured. The Bluetooth branch was fetched as a reference but excluded from analysis.

The project has clear modules, separate FreeRTOS tasks, hardware-generated step pulses, short E-STOP ISR operations, a simulator, diagnostics, event logging and automated tests. Priorities were deterministic stopping, pedal handling and agreement between wiring and firmware.

## Prioritized findings

### 1. Establish the E-STOP electrical truth table

Documentation conflict confirmed; actual wiring requires inspection. The original timing guide showed a 3.3 V pull-up and an NC chain to ground: LOW with a closed contact, HIGH on activation/cable break. Firmware instead expects LOW on fault and a FALLING edge. The hardware guide did not explain the required inversion.

Document healthy, pressed, cable break, supply loss and startup for one complete interface. Align code, diagrams and procedures. Consider independent physical driver disable, accounting for load movement when holding torque disappears. Verify ENA for the installed driver/revision: common-anode and common-cathode connections produce different optocoupler current, while code assumes LOW run/HIGH stop. Define behavior during MCU reset.

### 2. STOP can be overwritten or dispatched as the wrong command

Confirmed in reviewed `src/control/control.cpp:58–72,324–356`. All commands use a one-element `xQueueOverwrite` queue. A later START can replace STOP before the control tick. Separate peek/receive operations also let the STOP_JOG branch consume a normal STOP without stopping continuous motion.

Give STOP a separate priority latch, invalidate pending starts and receive once before dispatch. Define starts during stopping and test producer interleaving against production code.

### 3. Pedal can start at boot or after release

Confirmed in `src/main.cpp:166,203–214`. Previous state starts false, so an enabled pedal held at boot becomes a new press. Enabling while held can do the same. Release only stops an already RUNNING state; queued starts while IDLE survive a short press/release.

Require stable release before arming at boot/enable/reset. Debounce and cancel pending pedal starts on release regardless of state. Track which input source owns motion.

### 4. ADC failure retains old speed or selects another source

Confirmed in `src/motor/speed.cpp:105–121,327–335,389–390`. Failed reads retain `s_adsLastValue` without age limits; availability relies on startup probing. Values outside 100–3900 select the panel potentiometer automatically, potentially causing an unexpected speed change.

Timestamp valid samples, track errors, calibrate endpoints and publish an explicit pedal fault. Avoid automatic source fallback during pedal motion. Test disconnect/stuck-at faults with the panel set high.

### 5. Motion gate omits latched fault states

Confirmed in `src/safety/safety.cpp:123–125`: physical E-STOP and driver alarm are checked, but not `g_estopPending`/`estopLocked`. A brief fault edge followed by HIGH can leave an enable window before state latching.

Use a common latched gate cleared only by controlled reset. Test short edges around state checks, ENA and run/move calls. The initial mutex wait is bounded at 10 ms, but ESTOP transition subsequently calls `motor_halt` with `portMAX_DELAY`; the complete chain is not bounded. Keep disable independent of locks and defer blocking cleanup.

### 6. Startup must verify task creation

Confirmed in `src/main.cpp:346–355`: task-creation results are ignored while success is logged. Safety monitoring can be absent if its allocation fails but other tasks start. Check every result, require READY signals and keep motion blocked on failure. Check watchdog setup too.

### 7. Tests should exercise production policy

Native uses `test_build_src=false`. `src/control/test_logic.h` models a separate state machine/queue; its overwrite helper simply returns the second command. Passing this model does not validate the production FreeRTOS flow.

Extract shared hardware-independent policies. Test START/STOP interleaving, quick pedal press/release, held pedal at boot, ADC loss, faults during enable and failed task creation. Retain useful calculations while reducing duplicated code.

## Functional improvements after fixes

- Show active source and define takeover without speed jumps.
- Show surface speed with diameter/RPM: `mm/min = pi * diameter_mm * RPM`.
- Label pulse-derived RPM as calculated; it cannot detect slip/lost steps. Encoder feedback can provide measured speed/deviation.
- Preview program direction, diameter, speed, repeats and stop conditions.
- Build release/debug/mirror in CI and pin dependencies.
- Separate design targets from measurements. Measure worst-case stop response during rendering, flash writes and TIG HF interference.
