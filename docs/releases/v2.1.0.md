# v2.1.0 — V5 UI and motion/input reliability

This release brings the graphite/orange V5 interface to all 22 registered screens, adds idle-screen RPM +/− controls and makes the fault overlay more visible. STOP, pedal input, JOG renewal and persistence handling have also been hardened.

![V5 main screen](https://raw.githubusercontent.com/catorendal-a11y/DIY-Welding-Positioner-ESP32-P4/v2.1.0/docs/images/ui_runtime_v5/01_MAIN.png)

## Changes

- Large orange RPM panel with a native 104 px numeric font, CW/CCW selection and a wide START/STOP control.
- Red fault overlay displays input/alarm state and permits reset only after the fault is cleared. Reset returns to idle; it never starts rotation.
- STOP uses a separate latch and invalidates pending starts. JOG requires ongoing UI renewal and release cancels pending movement.
- Pedal control requires stable release before arming. Stale or failed active pedal data blocks motion; critical tasks must be ready before motion is accepted.
- Program drafts survive navigation; parameter snapshots and motor configuration are applied through the control task.
- Failed NVS saves remain pending and retry. Pending/error state is visible, and 300-second dimming stores correctly.
- Touch read errors release input. USB mirror writes use bounded waits and release remote input on failure.
- Pulse pause timing begins when the motor library reports stopped.
- README retains the original builder guides, demo, hardware photos, wiring references and bill of materials, with new runtime images and validation information.

Extract all files and double-click **Start Simulator.cmd**. No hardware or development tools needed. This is an offline UI simulator, separate from the USB live mirror. Its adjacent `.zip.sha256` file verifies this additional download.

- **release**: normal operation; start here.
- **debug**: serial logging for troubleshooting.
- **mirror**: USB-C pixel mirror and gated remote UI input.

Each variant has a standalone application `.bin` and a flashing bundle `.zip`. Use the bundled `FLASHING.md` for offsets and first-install instructions. The application image goes at **0x10000**, never at address zero. `SHA256SUMS.txt` provides download checksums. `LICENSES.txt` accompanies the binaries and is included in each bundle. The SVG design bundle is also included.

## Validation and hardware notes

Local validation passed 403 native tests, the actual LVGL simulator self-test and all three firmware builds. The V5 integration firmware was uploaded successfully with flash hash verification before the version-number update. This release's exact commit is checked by GitHub CI; the release firmware has not been uploaded to the connected device as part of release publication.

Firmware expects GPIO34 **HIGH healthy / LOW fault** and assumes ENA HIGH disables the driver. A bare NC contact to GND has the opposite polarity. Verify the assembled input circuit and cable-break behavior against the hardware guide. Physical motor response and stop latency require bench verification. TIG HF operation retains the grounded metal enclosure requirement.
