# v2.1.1 — LVGL 9.6, guided calibration and program editing

This release upgrades the display/motion libraries, gives the control task sole ownership of runtime motor operations, and adds guided setup, verified calibration and a clearer program editor while retaining the V5 dark graphite/orange design.

![New Program](https://raw.githubusercontent.com/catorendal-a11y/DIY-Welding-Positioner-ESP32-P4/v2.1.1/docs/images/program_v2/01_new_program.png)

## Changes

- LVGL 9.6.0, FastAccelStepper 1.4.0 at the exact upstream tag commit, Arduino 3.3.12 / IDF 5.5.5, PlatformIO 6.2.0 and Unity 2.7.0. Typed touch data, public LVGL APIs, style caching and simulator argument validation are adopted.
- Explicit RMT driver selection; typed move results; asynchronous force-stop cleanup blocks reset until queued motion drains. DIR timing cannot be reconfigured during motion. RMT channel creation now runs on Core 0 rather than assuming engine-task affinity also selects IRQ affinity.
- Single control-task motor owner, coherent snapshots, stale-status admission blocking and independent normal STOP supervision. The physical E-STOP remains an independent ENA inhibit.
- Four-stage setup: motor, direction, verified calibration and physical E-STOP function check. Existing valid settings migrate without forcing setup.
- Calibration: Align → Measure → Verify → Save with a separate runtime draft. Interrupted moves cannot qualify; correction must pass a completed verification and its save receipt. Failed writes can be retried.
- New/Edit Program: fixed 800×480 layout, separate run/available modes, full-screen name/RPM editors and visible Cancel. Strict input/UTF-8 limits, retained drafts, exact low-RPM display and fine adjustments in all mode editors.
- Precise RPM/fault information, improved production motion/storage tests, updated English builder documentation and actual LVGL captures.

## Downloads

[Portable Windows x64 simulator](https://github.com/catorendal-a11y/DIY-Welding-Positioner-ESP32-P4/releases/download/v2.1.1/welding-positioner-v2.1.1-simulator-windows-x64.zip): extract every file and open **Start Simulator.cmd**. It runs the production UI/control code with simulated hardware, requires no development tools and cannot move a real motor.

Firmware variants: **release** for normal operation, **debug** for serial diagnostics and **mirror** for gated USB-C screen mirroring. Each has an application `.bin` and a complete flashing `.zip`. Application offset is **0x10000**, never zero. Follow the bundled `FLASHING.md`. Existing matching NVS settings and presets are retained by an application-only update; a first installation uses the full bundle instructions.

`SHA256SUMS.txt` covers all downloads, including the simulator; its adjacent `.zip.sha256` also verifies the simulator ZIP. Bundles include build provenance and license notices. The SVG reference design bundle predates the latest guided/program layouts; the tagged documentation contains current runtime images.

## Validation and limits

438 native/production-control cases, six packaging regressions, actual upstream RMT encoder profiles for both buffer geometries, Linux/Windows LVGL regression, zero-failure layout audit and release/debug/mirror builds. Publication requires all six jobs to pass on the exact tagged master commit; firmware and simulator are taken from that run, not an unrelated local build.

This exact firmware has not been flashed or physically tested as part of publication. Verify real touch, movement, normal STOP, physical E-STOP, alarms, direction timing and persistence on the assembled controller. The 1.4.0 re-audit corrects IRQ-affinity and jitter claims; host tests do not establish a physical stop-time guarantee. GPIO34 remains HIGH healthy / LOW fault, and ENA HIGH is assumed to inhibit the driver. TIG HF operation retains the grounded enclosure requirement.
